# Real SMTP Email Sending Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the two dev-mode, console-log-only email functions with
real delivery via Gmail SMTP (`nodemailer`), with zero risk of the test
suite or local dev ever sending a real email, and with the PDF now
attached to the document-send email.

**Architecture:** A new `src/lib/mailer.ts` module wraps `nodemailer`
behind a small, plain-object interface (`isConfigured()` / `sendMail()`)
that both `sendVerificationEmail()` and `sendDocumentEmail()` call. The
module exports a testable `createMailer(config)` factory (so tests can
inject fake credentials and mock `nodemailer.createTransport` without any
network access) plus a singleton `mailer` built from real `env` values —
that singleton being a plain exported object, not a raw function export,
is also what makes it mockable from other test files (Node's ESM named
function exports are live bindings and can't be monkey-patched directly;
properties on an exported object can).

**Tech Stack:** `nodemailer` (new dependency) + `@types/nodemailer`.
Nothing else changes — same `node:test`/`supertest` backend test setup.

## Global Constraints

- `SMTP_USER`, `SMTP_APP_PASSWORD`, `SMTP_FROM_NAME` are **optional** env
  vars (not `required()`) — unset in dev/test/CI always, set only in the
  VPS production `.env`.
- Dev/test behavior is **unchanged**: when `SMTP_USER`/`SMTP_APP_PASSWORD`
  aren't both set, both email functions log to console exactly as they do
  today. No environment-name branching (`NODE_ENV === 'production'`) —
  gate purely on whether credentials are present.
- No real network/SMTP calls in any test. Test the nodemailer-calling
  code path entirely through mocking `nodemailer.createTransport` (a CJS
  package — its default export is a plain mutable object, safely
  mockable via `mock.method` from `node:test`) and through mocking the
  `mailer` singleton's own methods.
- `sendDocumentEmail()`'s signature changes to accept the PDF buffer as a
  4th parameter (`to, documentType, documentNumber, pdfBuffer`) — the one
  signature change in this plan, since dev-mode never attached anything
  before. `sendVerificationEmail()`'s signature does **not** change.
- `POST /api/auth/register` must not 500 if the verification email send
  throws — wrap it in try/catch, log the error, still return `201`.
- The `/send` route responses' `devMode` field must reflect reality
  (`!mailer.isConfigured()`), not the current hardcoded `true` — a real
  production send should report `devMode: false`.
- Plain-text email bodies only — no HTML templates.

```typescript
import nodemailer from 'nodemailer';
import { env } from '../env.js';

export interface MailAttachment {
  filename: string;
  content: Buffer;
  contentType?: string;
}

export interface MailOptions {
  to: string;
  subject: string;
  text: string;
  attachments?: MailAttachment[];
}

export interface Mailer {
  isConfigured(): boolean;
  sendMail(options: MailOptions): Promise<void>;
}

interface MailerConfig {
  user?: string;
  appPassword?: string;
  fromName: string;
}

export function createMailer(config: MailerConfig): Mailer {
  let transport: ReturnType<typeof nodemailer.createTransport> | null = null;

  function isConfigured(): boolean {
    return Boolean(config.user && config.appPassword);
  }

  function getTransport() {
    if (!transport) {
      transport = nodemailer.createTransport({
        service: 'gmail',
        auth: { user: config.user, pass: config.appPassword },
      });
    }
    return transport;
  }

  return {
    isConfigured,
    async sendMail(options: MailOptions): Promise<void> {
      if (!isConfigured()) {
        throw new Error('mailer.sendMail called while not configured — check isConfigured() first');
      }
      await getTransport().sendMail({
        from: `"${config.fromName}" <${config.user}>`,
        to: options.to,
        subject: options.subject,
        text: options.text,
        attachments: options.attachments,
      });
    },
  };
}

// The real singleton, built from actual env values. sendVerificationEmail()
// and sendDocumentEmail() call this — see src/auth/email.ts and
// src/documents/sendDocumentEmail.ts. Exported as a plain object (not raw
// named functions) specifically so tests in other files can mock.method()
// its properties without hitting real SMTP.
export const mailer = createMailer({
  user: env.smtpUser,
  appPassword: env.smtpAppPassword,
  fromName: env.smtpFromName,
});
```
